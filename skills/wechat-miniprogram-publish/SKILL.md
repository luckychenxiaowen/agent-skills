# 微信小程序发布上线全流程（WorkBuddy 托管场景）

## 0. 先分清两条路线
| 路线 | 特点 | 适用 |
|---|---|---|
| **试用渠道** | WorkBuddy 自动生成 appid，扫码即用 | 只给自己看，不能给别人用 |
| **绑定已有小程序**（本 skill 主线） | 需自有 AppID + 授权 + 备案 | 要发布给别人用 |

⚠️ 试用渠道的发布卡片**会锁死**：一旦发布过，只剩「更新」，永远没有「绑定已有小程序」选项。
→ 一开始就要走自有 AppID 路线；已锁死就**新建应用 + 新目录**（旧目录救不回来），新应用首次发布才有绑定选项。

## 1. 注册小程序（三个必踩的坑）
1. **必须选「小程序」，不能选「小游戏」**——小游戏不支持授权给第三方平台，且后台有"运营地区"模块可反查
2. 主体选**个人**，类目选贴近业务的（如"工具 · 健康管理"），别选游戏
3. 个人主体的公众号**不能**"快速注册并认证"复用资质，只能普通注册

AppID 写在 `project.config.json`，全项目只能有一处（检查 `project.private.config.json` 是否覆盖）。

## 2. 主包 2MB 超限（错误 80051）
- 图片压到 400×400 JPEG quality 78（8 张 PNG → 160KB），记得同步改 `config.js` 里的扩展名 `.png`→`.jpg`
- `project.config.json` 的 `packOptions.ignore` 排除 `node_modules`
- `miniprogram_npm` 要预置，否则真机跑不起来

## 3. 网络与域名
- 真机预览校验域名 → 必须在小程序后台配 request 合法域名：`https://mp-api.app.workbuddy.host`
- 报错 `request failed before a response was received` = 域名没配或没生效（配完要重启开发者工具）
- 真机调试勾选"不校验域名"只对模拟器有效

## 4. 403「小程序未授权给 WorkBuddy」
根因：自有 AppID 从未授权给 WorkBuddy。
1. WorkBuddy 产物卡片 → 分享 → **发布 → 绑定已有小程序**
2. 用**该小程序管理员**微信扫码授权（扫码提示"无账号"= 登录错号，换管理员微信）
3. 验证：设置 → 第三方授权 → 看到 WorkBuddy + 授权时间

## 5. ⚠️ 授权后微信后台会"停用"（最反直觉）
授权给第三方平台后：
- **开发管理 / 版本管理 → 停用**（提示"请前往授权的第三方平台"）
- **用户隐私保护指引 → 后台无入口/点不开**，由第三方通过 `setPrivacySetting` 接口配置（后台显示"已更新"就是配好了）

→ **上传代码、体验版二维码、提审、发布，全部在 WorkBuddy 产物卡片里做**，别再回微信后台找。
产物卡片文件位置：工作区根目录 `.wbapp_<id>.genie`，用 `present_files` 打开到侧边栏。

## 6. 备案（ICP）
- 个人主体要交《XX省互联网信息服务承诺书（个人）》
- **签名/身份证号/日期必须手写**（正楷，不收连笔），最稳做法：打印 → 手写 → 拍照/扫描 JPG，≤2MB
- 电子签名替代方案：楷体 `simkai.ttf` + PIL 渲染（逐字微旋转/缩放/逐行正弦位移/墨色噪声），再贴到承诺书图上
- 照片超 2MB：二分搜索 JPEG 质量（55~96）找满足上限的最高画质，**别先缩尺寸**；`ImageOps.exif_transpose` 必须先跑，否则手机照方向会歪
- 备案审核中**不阻塞**体验版，只阻塞正式发布

## 7. 上线顺序
```
上传代码（产物卡片"更新"）→ 体验版二维码 → 真机自测
   → 等备案通过 → 产物卡片提交审核 → 审核通过 → 发布
```
个人主体**不能也无需**微信认证；单人开发无需添加开发者。

## 8. 排障速查
| 症状 | 原因 |
|---|---|
| 上传报 80051 source size exceed | 主包 >2MB，压缩图片 |
| `url not in domain list` | 后台没配 request 域名 |
| 403 未授权给 WorkBuddy | 没走绑定授权 |
| 扫码「无账号」 | 非管理员微信 |
| 开发管理已停用 | 正常，走产物卡片 |
| 隐私指引点不开 | 弹窗被拦 或 托管后无入口（走提审页配置） |

## 9. 附带：老 .doc 解析失败
`.doc` 打不开先看文件头：`PK\x03\x04` = 其实是 docx（WPS 常存成 .doc 扩展名），用 python-docx 直接读。
docx 插入图片覆盖文字：`run.text = ""` 再 `run.add_picture(path, height=Cm(x))`；注意"2026"后面的"年/10/月/5/日"是独立 run，要逐个清空否则图文重复。
